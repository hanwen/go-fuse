# Go-FUSE v3

This document lists the changes between v2.12 and v3. The import path
is now `github.com/hanwen/go-fuse/v3`. Go 1.25 or newer is required.

Most users of the `fs` package only need to change the import path.
Users of the raw `fuse.RawFileSystem` API need more changes.

For an agent-driven upgrade, see
[skills/upgrade-go-fuse-v3/SKILL.md](skills/upgrade-go-fuse-v3/SKILL.md).

## Removed

* `fuse/nodefs` and `fuse/pathfs` are gone. They were deprecated in
  2019. Port such file systems to the `fs` package.
* `fuse.Context` is gone. Do not cast a `context.Context` to
  `*fuse.Context`. Use `fuse.FromContext` or `fuse.CallFromContext`.
* `Server.SetDebug` and `RawFileSystem.SetDebug` are gone. Set
  `MountOptions.Debug` before mounting, or set `MountOptions.Logger`.
* `Server.RecordLatencies` and `LatencyMap` are gone. They did
  nothing. Wrap the `RawFileSystem` to collect metrics.
* The notify methods on `ProtocolServer` (`InodeNotify`,
  `EntryNotify`, `DeleteNotify`, `InodeNotifyStoreCache`,
  `InodeRetrieveCache`) are gone. Use `Conn.Notify()` instead.
* `InitIn.SupportsNotify` and the `NOTIFY_*` constants are gone.
  Call the function in `Conn.Notify()` and treat `ENOSYS` as
  unsupported. This also covers transports that do not support
  notifications.

## Changed in `fuse`

* All `RawFileSystem` methods take `ctx context.Context` instead of
  `cancel <-chan struct{}`. The context is canceled when the kernel
  interrupts the request. `ReleaseDir` now takes a `ctx` too.
* The request context is allocated per request. The file system may
  keep it after the method returns.
* `FromContext` returns `Caller` instead of `*Caller`.
  `NewContext` takes `Caller` instead of `*Caller`.
* `RawFileSystem.Init(*Server)` is renamed to `OnConnect(*Conn)`.
  `Conn` describes the negotiated connection. It gives access to the
  INIT request (`In`), the INIT reply (`Out`), notifications
  (`Notify`) and passthrough backing files (`Backing`). The
  functions in `Notify` and `Backing` may be replaced in `OnConnect`,
  for example to add metrics or fault injection.
* There is a new `RawFileSystem.Init(in *InitIn, out *InitOut)`. It
  is called with the INIT request, and may change the reply before it
  is sent. `MountOptions.InitHandler` does the same from the mount
  options.
* Unmounting no longer depends on `MountOptions`. It tries
  `umount(2)`, and on Linux falls back to `fusermount -u`.
* If `fusermount` is not installed, go-fuse calls `mount(2)` itself.
* `Server.Serve` is `Start` followed by `Wait`. `Wait` returns when
  the server is closed, which happens on unmount, on `Shutdown`, or
  when reading from the device fails. A read error now closes the
  whole server.

## New in `fuse`

* `Call`, from `CallFromContext(ctx)`, exposes request details that
  the `XxxIn` structs lack: `Caller`, `KillSuidgid`, `SuppGroups`,
  `SecCtx`, and `Input` for a copy of the raw input struct. Only
  `Caller` works after the method returns.
* `Mount` and `Dev` split mounting from serving. `NewServer` is now
  `NewMount`, `Mount.Mount` and `NewServerFromDev` in sequence.
* `Server.Start`, `Server.Stop` and `Server.Shutdown` control the
  request loop. `Stop` stops reading but keeps the connection open.
* `Server.Dev` returns a duplicate of the device fd together with the
  negotiated connection. Pass it to another process, and serve it
  there with `NewServerFromDev`. Together with `Stop`, this hands a
  mount to a new server without unmounting.
* On Linux, readers wait in `epoll_wait(2)`, so `Stop` can interrupt
  them. This needs Linux 4.5 or newer.

## Changed in `fs`

* The `fs` node API is unchanged.
* `Inode.Parents` returns every (name, parent) pair of an inode.
* If a non-directory leaves `Attr.Nlink` at 0, the bridge fills in
  the number of parents.
* A directory can only have one parent. Use `MvChild` to move it.
* If a directory has no `NodeMknoder`, MKNOD of a regular file uses
  `NodeCreater`.
* `LoopbackNode` keeps an open descriptor for the root.
  `LoopbackRoot.Close` closes it. `LoopbackNode.OnForget` calls it
  for the root node, so embedders that override `OnForget` must call
  `LoopbackNode.OnForget` too.

## Bug fixes

* fs: seeking a directory to offset 0 re-reads the directory.
* fs: `LoopbackNode` resolves paths beneath the root descriptor, and
  does not follow symlinks. Before, a symlink swapped into the backing
  tree could redirect operations outside the root.
* fs: `LoopbackNode.Statx` does not follow symlinks.
* fs: `LoopbackNode.Setxattr` clears the setgid bit when the kernel
  asks for it (`SETXATTR_ACL_KILL_SGID`).
* fuse: unmounting retries only on `EBUSY`, so other errors are
  reported right away.

## New platforms and transports

* OpenBSD (fuse(4), protocol 7.19).
* `fskit`: mount on macOS through FSKit (macFUSE 5.3.0 or newer).
* `virtiofs`: support for cloud-hypervisor, several request queues and
  `SET_MEM_TABLE`.
